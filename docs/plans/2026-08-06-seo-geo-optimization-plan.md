# SEO / GEO 全量优化方案

## 目标

在不改变博客视觉定位和现有文章 URL 的前提下，提升搜索引擎抓取、理解、收录与点击能力，同时让 AI 搜索和其他机器客户端可以稳定发现、读取、引用博客内容。优化范围覆盖：

1. 内容资产与主题结构
2. 页面语义与传统 SEO
3. GEO 机器入口与公开知识库
4. 结构化数据与作者实体
5. 数据驱动的赢家页面
6. 性能、缓存和可访问性基础

## 现状基线

- 19 篇公开文章，主题集中在 AI、Java、Redis、认证安全、部署。
- Sitemap、RSS、canonical、Open Graph、文章 BlogPosting JSON-LD 已存在。
- 文章页可被静态抓取，但非文章页面普遍存在布局兜底 H1 与页面 H1 重复。
- 搜索页被排除出 Sitemap，但没有明确的 `noindex,follow`。
- 文章正文之间的显式内部链接很少，主题权威主要依赖组件自动推荐。
- Umami 已能返回按路径 PV，但文章列表只有最新/最早排序，没有赢家视图。
- AI 搜索向量索引代码已存在，但站内 AI 搜索默认关闭，也没有公开的 `llms.txt`/知识库目录。
- 首页和公共资源包含较大的视频、GIF、图片与字体，需降低首屏网络压力。

## 设计与实现范围

### 一、页面语义和索引控制

- 为 `MainGridLayout` 增加显式的页面 H1 控制参数。
- 文章页、首页、归档、分类、列表、搜索、关于、友链等页面各自保留唯一且有意义的 H1。
- 删除空的布局兜底 H1，避免首页与功能页出现两个 H1。
- 搜索页输出 `noindex,follow`，并继续从 Sitemap 排除。
- canonical 统一使用不带查询参数的规范路径；Open Graph URL 与 canonical 保持一致。
- 为首页补充明确 description；为功能页使用页面专属 description，避免全部回退到站点描述。

### 二、结构化数据和实体

- 首页输出 `WebSite`、`Person`、`ProfilePage` 相关 JSON-LD。
- 文章页扩展 `BlogPosting`：补充 `articleSection`、`wordCount`、`dateModified`、`url`、`isPartOf` 和稳定的作者/站点实体。
- 文章页输出 `BreadcrumbList`，形成“首页 → 分类 → 文章”的机器路径。
- 使用站点头像或安全的 favicon 作为作者/发布者图像，保证绝对 URL。
- 继续对 JSON-LD 做 `<` 转义，避免正文内容破坏脚本。

### 三、公开知识库和机器入口

新增静态入口：

- `/llms.txt`：站点定位、作者、主题、核心入口和精选文章。
- `/knowledge/index.json`：文章目录、摘要、分类、标签、日期、规范 URL、章节目录。
- `/knowledge/articles/{slug}.json`：单篇文章的机器可读元数据、章节、纯文本摘要和规范 URL。
- `/knowledge/articles/{slug}.md`：面向 AI/阅读器的纯 Markdown 文章入口，保留标题、元数据和正文。

知识库只收录非草稿、非加密文章；内容以静态生成方式输出，不依赖运行时数据库。文章 slug 复用现有 `src/content/posts` 路径，避免产生第二套 URL 体系。

### 四、内容结构和内部链接

- 增加专题页 `/topics/`，展示 AI、认证与安全、Redis 与高性能、Java 并发、部署实践五个主题。专题页和机器入口保留，但不在首页和主导航中突出展示，作为按需访问的知识索引。
- 每个专题页输出主题说明、推荐文章、文章摘要、标签和互链。
- 文章页增加“所属专题”和相关文章链接；保留现有基于标签/分类的相关文章组件。
- 文章页保留小型“所属专题”内链，让专题仍能被按需访问；首页不展示专题卡片，避免机器知识入口干扰首页视觉叙事。
- 给文章 frontmatter 增加可选 `topics` 字段，未填写时按分类/标签自动归类。
- 文章摘要优先使用 frontmatter description；缺失时从正文生成安全的纯文本摘要。

### 五、赢家识别与页面强化

- 复用 Umami 路径统计，把文章列表排序扩展为“最新、最早、访问量”。
- 访问量排序失败时回退到最新排序，不阻塞文章阅读。
- 在首页“热门文章”区域展示可静态抓取的内容链接；动态 PV 到达后只更新数字，不替换链接结构。
- 增加文章列表的可读 `time`、摘要和分类/标签链接，确保客户端增强失败时仍可抓取。
- 统计配置开启 Web Vitals 采集；不启用会话回放，保持隐私边界。
- 为文章数据保留更新时间字段，并让 Sitemap `lastmod` 优先使用 `updated`。

### 六、性能、缓存和资源

- 为首页背景图和首屏关键图片补充尺寸、解码和加载优先级信息，避免布局偏移。
- 首页背景视频使用 `preload="none"` 或按交互/可见性延迟加载，移动端不加载桌面资源。
- 为公共图片、字体、视频和音频增加分层缓存策略；哈希资源继续 immutable，非哈希资源使用短缓存并 revalidate。
- 不在本次任务中删除用户资产；只调整加载策略和响应头。
- 保持现有构建压缩和代码分块，避免将大型交互组件提前加载到文章首屏。

## 数据流

```text
Markdown frontmatter + 正文
        ├─ Astro 文章页 ── SEO meta + JSON-LD + 专题/相关文章
        ├─ /knowledge/* ── JSON / Markdown / llms.txt
        ├─ Sitemap / RSS ── 搜索引擎与订阅客户端
        ├─ Pagefind ── 站内全文检索
        └─ Umami path metrics ── 赢家排序与首页热门内容
```

## 错误处理和兼容性

- 公开知识库生成时跳过草稿和密码文章，单篇不存在时返回 404。
- Umami 不可用、接口超时或返回异常时，页面维持最新排序并显示占位访问量。
- 主题数据为空时专题页仍输出稳定的空状态，不产生无效链接。
- 不修改既有文章 URL；新增入口全部使用尾斜杠规范。
- 继续兼容 Swup 客户端导航和无 JavaScript 的静态抓取。
